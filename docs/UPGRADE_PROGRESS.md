## 已知限制与未扩展项

- 已连接真实 MySQL 并验证数据范围；未调用真实 LLM，避免在未确认费用边界时消耗外部服务。
- 已使用真实 Ephemeral Chroma 验证 owner `where` 过滤；未对现有持久化记忆集合写入测试数据。
- pytest 的全局任务库强制使用会话级临时目录；Compose 的 App/Worker 使用共享 `task_runtime_data` named volume，避免测试进程与 Windows bind mount 上的 SQLite WAL 互相干扰。原宿主机任务库保留未删除。
- 未进行真实浏览器人工验收；已完成 Vue 类型检查和生产构建。
- 自然语言解析仍是受控确定性子集，不声称覆盖任意表达；未知指标、字段或关键口径需继续澄清或拒绝。
- 未调用真实收费 LLM，因此阶段三没有新增开放式 Text2SQL 下游正确率；客服侧只验证了 1 条确定性业务配方。旧冻结准确率不冒充本次结果。
- 客服迁移集仅 8 条且以当前目录人工策划，不能作为通用 Schema 泛化结论；后续应加入冻结陌生表达和更多同名字段。
- 当前 ACL 只有 public/精确 owner；尚无组织/部门层级权限，也未验证跨数据库方言或跨库连接。
- 报告错误回归使用模拟 LLM 输出完成，未调用真实收费 LLM；因此只证明校验与一次修复闭环，不声称真实模型的报告通过率。
- 当前报告程序校验只覆盖物化 SQL 数值事实及其维度/期间/排序引用；分析模型和预测模型输出尚未转换为同等级事实条目。
- 阶段五仅运行每组 5 条已知模板的同模型付费对照；没有覆盖陌生查询、报告、多轮或恢复场景，也没有重复运行估计波动，不能作为完整架构优越性或统计显著性结论。
- 检查点当前是诊断快照，不支持任意节点原地继续；在 SQL/LLM/分析节点统一幂等前，接口明确拒绝该模式并要求从头重试。
- SQLite 任务存储只验收了单主机进程竞争与租约故障；尚未做多主机和真实模型压力测试，不能作为生产 SLA。
- 成本统计只有配置实际模型输入/输出单价后才有意义；默认单价为 0，不将其解释为真实零成本。
