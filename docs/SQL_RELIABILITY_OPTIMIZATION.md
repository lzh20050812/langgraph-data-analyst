# SQL 语义可靠性优化路径

当前正式实验表明，系统的主要瓶颈不是预测模型或多 Agent 编排，而是 SQL 的业务口径正确性。后续只沿这一条路径优化。

## 第一阶段：语义指标注册表

为退货率、流失率、复购、客单价、季度趋势、年龄段、Top-N 等高频指标定义：来源表、基础字段、计算公式、单位、默认时间粒度和禁止连接。注册表不存整条测试 SQL，而存可复用业务语义。

## 第二阶段：查询形状契约

TaskPlan 在生成 SQL 前声明预期维度、指标、列数、排序与粒度。SQL 执行后检查结果形状；例如“会员等级数量和占比”必须返回等级、数量、0–100 占比三列，不能只凭执行成功放行。

## 第三阶段：安全降级

字段归属校验发现不可连接表时，不让 LLM重复猜测同一不存在的键。改为回退到单表可回答指标，并在证据中明确“由于缺少订单—商品键，无法做订单级品类归因”。

## 验收门槛

- 15 条 SQL 任务结果集等价准确率至少 80%；
- SQL 执行成功率 100%，写操作拦截率 100%；
- 不再出现 `orders.product_id` 等不存在字段的重复重试；
- 单任务 P95 不超过 20 秒，任何 SELECT 最长 60 秒。

## 2026-08-12 验收结果

- 15 条固定 SQL 子集：15/15，结果集等价准确率 100%；
- 完整 50 条项目任务：50/50，TCS 100%；
- 15 条未见业务改写句：15/15 命中同一语义配方，并在真实 MySQL 上通过结果形状契约；
- Q23 折扣分析：由 68.05 秒失败降为 2.16 秒成功；
- Q45 退货原因报告：由字段归属失败改为合法订单—客户连接并成功生成报告；
- 完整回归中位耗时 3.30 秒，P95 19.87 秒，满足门槛。

上述 100% 仅适用于当前固定任务集和已登记指标目录。未登记的开放式 SQL 仍由
LLM 生成，不能外推为任意自然语言查询均达到 100%。

## 消融证据

在同一版代码上关闭业务语义层后，15条SQL准确率由100%下降为46.67%，错误数
从0增加到8；精确McNemar检验双侧 p=0.0078。详细数据见
`evaluation/results/semantic_ablation_20260812/ablation_report.md`。
