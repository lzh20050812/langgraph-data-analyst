### 2.2 API 请求隔离和资源保护

新增 `api/result_store.py`：

- 每次 `/query` 返回独立 `request_id`
- 通过 `/charts/{request_id}` 和 `/report/{request_id}` 获取对应结果
- 线程安全、最多保存 100 条、默认保留 1 小时
- 只保存 intent、report 和 charts，不保存完整 Agent state

新增 `api/query_limiter.py`：

- 默认最多同时处理 4 个查询
- 超出容量立即返回 HTTP 429，并带 `Retry-After: 2`
- 异常路径也会释放并发槽位

Docker 内进行过 5 个并发查询验证：4 个成功，1 个在约 0.052 秒内返回 429，符合设计。

当前结果存储是单进程内存实现。单容器演示没有问题，但多 worker 或多实例部署必须换成 Redis 等共享存储。

### 2.3 可观测性和输入校验

`api/main.py` 已加入请求中间件，每个 HTTP 响应都会带：

- `X-Request-ID`
- `X-Process-Time-Ms`

访问日志以 JSON 输出到标准输出，包含请求 ID、方法、路径、状态码和耗时。已经在 Docker 实际日志中核对过日志、响应体和响应头中的请求 ID。

查询输入现有约束：

- 自动去除首尾空白
- 长度为 1 至 1000 个字符
- intent 仅允许 `sql_query`、`analysis`、`prediction`、`mixed`
- 空值或非法值返回 HTTP 422

### 2.4 数据库最小权限部署

新增 `storage/mysql/provision_reader.py`，Docker Compose 拆分为：

- `mysql`：MySQL 8.0
- `db-init`：一次性使用管理员账号装载数据并创建只读账号，成功后退出 0
- `app`：仅使用 `analytics_reader` 连接数据库

已经核对运行账号只拥有 `USAGE` 和 `SELECT` on `ai_analytics.*`。交接文档不记录任何真实密码或 API Key；配置值应从本地 `.env` 获取。

为了避免 app 和 db-init 共享构建定义时出现 Docker Bake 重复构建问题，推荐启动流程是先构建 app，再禁止重建启动：

```powershell
docker compose -p ai_analytics -f docker/docker-compose.yml build app
docker compose -p ai_analytics -f docker/docker-compose.yml up -d --no-build
```

### 2.5 健康检查与运行超时

已实现：

- `/health/live`：只检查 API 进程存活
- `/health/ready`：检查 MySQL 连接和 LLM 配置，降级时返回 503
- `/health`：向后兼容入口
- Docker healthcheck 使用 `/health/ready`
- OpenAI 请求超时默认 30 秒，最多重试 2 次
- 数据库启用连接预检，连接池等待 10 秒，连接超时 5 秒，查询上限 60 秒

`/health/ready` 只检查 LLM 是否配置，不会发起计费的外部模型请求。

## 5. 已知限制和建议优先级

1. **公开部署前增加认证。** 当前 API 没有 API Key 或登录校验，本地毕设演示足够，但不适合直接公开到互联网。认证会影响前端和调用方式，应先确认部署范围再实现。
2. **多实例时引入 Redis。** 当前 request result store 仅在单进程内有效。
3. **总任务超时需要异步作业架构。** LLM 和数据库已有单项超时，但 Python 中正在运行的线程不能被安全强杀；若必须提供严格的端到端超时，建议采用后台队列、任务状态和取消机制。
4. **优化通用图表体验。** SQL-only 请求现在允许返回 0 张图，这是设计行为；可增加通用结果集自动图表生成。
5. **冷启动和查询延迟仍较高。** 嵌入模型或分析链可能使单次查询耗时超过 20 秒，并发限制能防止过载，但还可做模型预热、缓存和阶段耗时分析。
6. **处理测试弃用警告。** 评估升级 Starlette/httpx 测试栈，但不要为了消除非功能警告冒险破坏稳定版本。
7. **CI 尚待真实运行。** 提交并推送后应观察 GitHub Actions，并核对 Linux CPU 环境中的完整安装与测试。
8. **依赖不是哈希锁定。** 当前直接依赖精确固定，已满足较好的可复现性；若追求供应链级复现，可再生成带哈希的锁文件。
