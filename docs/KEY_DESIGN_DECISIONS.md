# 关键设计决策记录

> 版本：2026.09，日期：2026-09-19。每项均记录问题、备选方案、取舍、验证和剩余边界。

## ADR-01：业务指标由受控目录定义

- 问题：模型可以生成语法正确但业务口径错误的 SQL。
- 备选：完全自由 Text2SQL；把所有示例塞进 Prompt；版本化指标目录加确定性配方。
- 决策：稳定高风险指标使用版本化目录和 Query Contract，开放问题才进入受约束生成。
- 证据：阶段四条件/粒度/报告校验回归；阶段五受控组 5/5 严格答案等价。
- 代价：新增指标需要配置，不能宣称任意业务零配置接入。

## ADR-02：结构知识与业务知识分层检索

- 问题：字段关系、指标公式和使用限制混在同一索引中会污染召回与权限边界。
- 备选：全量 Schema Prompt；单一向量集合；结构/业务目录分离并融合词法与向量。
- 决策：分层目录、内容指纹、数据源和 owner 过滤，融合参数只在验证集选择。
- 证据：28 条独立测试 Hybrid Field R@5 86.31%；相对词法仅 +0.60pp 且置信区间跨 0，负结果保留。
- 代价：需要索引版本管理；小型第二 Schema 不能证明通用迁移。

## ADR-03：报告必须引用物化事实

- 问题：流畅报告可能改写数值、期间、名称或排名。
- 备选：只依赖 Prompt；模型自评；程序化事实引用校验。
- 决策：EvidenceBundle 记录来源、结果行和事实编号；报告同一行引用 `[F#]`，失败最多修复一次后闭合。
- 证据：错误数值、名称、年份、排名和未知引用回归全部被拦截。
- 代价：当前主要覆盖物化 SQL 数值事实，预测/分析模型输出尚未完全事实化。

## ADR-04：任务使用持久状态机和执行令牌

- 问题：Worker 中断、租约交接和迟到结果可能覆盖正确终态。
- 备选：进程内 Future；仅记录 worker_id；状态机加每次领取唯一令牌。
- 决策：SQLite WAL 保存任务、事件、检查点和租约；内嵌及外部执行都由令牌 fencing。
- 证据：并发唯一领取、租约接管、旧令牌事件/检查点/终态拒写以及 SSE 重连测试。
- 代价：SQLite 只适合单主机；多主机目标触发 PostgreSQL 元数据迁移。

## ADR-05：检查点不等于可安全续跑

- 问题：任意节点恢复会重复模型计费、SQL 或下游副作用。
- 备选：把从头重跑称为恢复；直接反序列化状态继续；在节点幂等前拒绝检查点继续。
- 决策：`restart` 创建带父任务和风险清单的新任务；`checkpoint` 当前返回 409。
- 证据：API 和故障测试验证模式、父任务、风险记录和安全拒绝。
- 代价：检查点现阶段用于诊断，真正续跑仍需节点级幂等键和外部调用账本。

## ADR-06：不提前引入 Redis 或消息队列

- 问题：增加分布式组件可能产生多个真相源，而当前未测得队列瓶颈。
- 备选：Redis 列表/Streams；独立消息队列；SQLite 原子领取；PostgreSQL `SKIP LOCKED`。
- 决策：单主机继续 SQLite；需要多主机/高可用时优先把任务元数据迁到 PostgreSQL，确认分发瓶颈后再选一个队列实现。
- 证据：当前 4 并发、20 排队目标及单主机竞争/故障回归；没有真实模型容量证据支持新增组件。
- 代价：不提供多主机生产 SLA。

## ADR-07：缓存演示与实时分析严格分标

- 问题：答辩网络波动需要离线兜底，但缓存结果容易被误述为实时模型输出。
- 备选：只做在线演示；静态截图；持久化、显式标注的固定数据快照。
- 决策：缓存场景创建普通任务和审计记录，但返回 `result_mode=cached_demo`、来源声明和演示步骤；实时任务返回 `live_agent`。
- 证据：前端构建与契约测试同时检查“缓存演示结果”和“实时 Agent 分析”标签。
- 代价：缓存演示只能证明交互和固定证据链，不能证明现场模型质量或吞吐。
